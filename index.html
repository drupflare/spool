    🧵 spool

    An incremental application replica for the browser

    spool keeps a replica of what a page needs on the visitor's device. The server sends templates and authorised, versioned data. A service worker stores them and computes eligible pages on the device, so a repeat view makes no request and costs the server no work.

    It runs on any runtime that speaks Request and Response, bridges node:http for the rest, and has no runtime dependencies. A site with no server code can load it from two files and a manifest.

    🎯 Why Spool

    A response is a deterministic transformation of a set of authorised, versioned dependencies. The server half names those dependencies and sends the snapshot the visitor may hold. The worker keeps a graph of records, projections and responses, with their versions, and syncs only what the next page needs.

    Your application keeps every write, every access decision and every page it cannot reproduce safely on the device. A route the worker cannot answer goes to the network, so adopting spool changes no page that was not declared.

    docs/impact.md holds the energy model and the measurements behind it.

    📥 Install

    Package

    bun add @drupflare/spool

    The package ships ES modules and type declarations. Node, Deno, Bun, Workers and bundlers import it directly.

    CDN Script

    A page can load the runtime from cdn.drupflare.com with a Subresource Integrity hash. The release notes list the hash for each version.

    <script
      src="https://cdn.drupflare.com/spool/<version>/client.js"
      integrity="sha384-<hash from the release notes>"
      crossorigin="anonymous"
      defer
      data-spool-client
    ></script>

    Page Runtime shows how createSpool injects the same tag.

    Direct Files

    spool-sw.js, client.js and manifest.json are attached to every GitHub release and published under https://cdn.drupflare.com/spool/<version>/. A site that serves them as plain files needs no server library. See Static Sites.

    🚀 Quick Start

    Every runtime below makes the same three moves:

    1. Declare the routes the device may answer, and the version store that tracks changes.
    2. Wrap the application's handler with spool.handle. It answers /.spool/* and /spool-sw.js.
    3. Send the client tag, which is the script tag for the page runtime. handle injects it into every HTML page the application returns, and spool.decorate does the same where there is no Fetch response to wrap.

    Declare Routes

    A route has a path pattern, a strategy, the tags it depends on and a load function that returns the data for one page. load runs on the server and may check the visitor's identity. Only its result reaches the device.

    import { defineRoute } from '@drupflare/spool/server';

    export const routes = [
      defineRoute('/node/:id', {
        strategy: 'template',
        template: {
          source:
            '<!doctype html><html><head><title>Node {{id}}</title></head><body><h1>Node {{id}}</h1></body></html>'
        },
        depends: (ctx) => [`node:${ctx.params['id']}`],
        load: (ctx) => ({ id: ctx.params['id'] })
      })
    ];

    const escape = (text: string) => text.replace(/[&<>"']/g, (c) => `&#${c.charCodeAt(0)};`);

    export const page = (request: Request) => {
      const id = escape(new URL(request.url).pathname.split('/')[2] ?? '');
      return new Response(
        `<!doctype html><html><head><title>Node ${id}</title></head><body><h1>Node ${id}</h1></body></html>`,
        { headers: { 'content-type': 'text/html; charset=utf-8' } }
      );
    };

    page stands in for your application. The page it returns has to match what the template renders from the route's data, because the device renders the same route without asking you.

    The version store records which tags changed. memoryStore serves a single process. Every other deployment needs a store that all instances share, which is any object with three methods: bump(tags), cursor() and diff(from). On Cloudflare, durableObjectStore keeps the vector in a Durable Object.

    import { memoryStore } from '@drupflare/spool/stores';

    export const store = memoryStore();

    createSpool joins the two:

    import { createSpool } from '@drupflare/spool/server';
    import { routes } from './routes';
    import { store } from './store';

    export const spool = createSpool({ routes, store });

    After a write, call await spool.invalidate(['node:1']) with the tags it touched. Devices holding a page that depends on them fetch a fresh copy before they show it again.

    📦 Page Runtime

    handle and decorate inject one script tag into each HTML page. By default the script is served from the same origin at /.spool/<version>/client.js, which suits a strict script-src 'self' policy. To serve it from cdn.drupflare.com instead, pass the integrity hash that the release notes list for your version. The URL defaults to that version's file.

    import { createSpool } from '@drupflare/spool/server';
    import { memoryStore } from '@drupflare/spool/stores';
    import { routes } from './routes';

    export const spool = createSpool({
      routes,
      store: memoryStore(),
      cdn: { integrity: 'sha384-<hash from the release notes>' }
    });

    The CDN copy carries Cache-Control: public, max-age=31536000, immutable and the browser checks it against the hash, so a changed file never runs. Release files are never overwritten. If the script fails to load, the page works as it did before.

    The script registers /spool-sw.js and exposes window.spool.ready, which resolves to the client handle or to null where service workers do not exist. To bundle the runtime yourself, import register from @drupflare/spool/client.

    Activity Hooks

    A loop that keeps running while nobody can see its output costs the visitor's device power. The page runtime exposes window.spool.activity.register, which lets a page hand spool a pause and a resume for one of its own loops. Spool calls pause while the loop's target is off screen and after the page has been hidden for hiddenAfterMs, and calls resume when neither holds.

    import { createActivity } from '@drupflare/spool/client';

    const canvas = document.querySelector('canvas') as HTMLCanvasElement;
    let frame = 0;

    const draw = () => {
      canvas.style.transform = `translateX(${(performance.now() / 10) % 200}px)`;
      frame = requestAnimationFrame(draw);
    };

    draw();

    export const stop = createActivity().register(
      { pause: () => cancelAnimationFrame(frame), resume: draw },
      { target: canvas, hiddenAfterMs: 10_000 }
    );

    target is optional, and without it only the hidden-page rule applies. hiddenAfterMs defaults to 10000, and 0 pauses at once. register returns a function that stops watching and resumes the loop if it is paused. Spool does not touch setInterval, requestAnimationFrame, fetch, audio, WebRTC or any element the page did not name, and a pause or resume that throws is logged once. Where IntersectionObserver is missing the target counts as on screen. On the one desktop measured, the off-screen pause lowered power for a page whose frame loop kept running, and the hidden-page pause showed no saving for a once-a-second poll. Both readings are in docs/impact.md.

    Cloudflare Workers

    Bind the Durable Object that holds the version vector, then pass its namespace to durableObjectStore.

    {
      "durable_objects": { "bindings": [{ "name": "SPOOL_VERSIONS", "class_name": "SpoolVersions" }] },
      "migrations": [{ "tag": "v1", "new_sqlite_classes": ["SpoolVersions"] }]
    }

    import { createSpool } from '@drupflare/spool/server';
    import { durableObjectStore } from '@drupflare/spool/stores/durable-object';
    import { page, routes } from './routes';

    export { SpoolVersions } from '@drupflare/spool/stores/durable-object';

    export default {
      fetch(request: Request, env: Cloudflare.Env) {
        const spool = createSpool({ routes, store: durableObjectStore(env.SPOOL_VERSIONS) });
        return spool.handle(request, page);
      }
    };

    Cloudflare Pages Functions

    A function takes a context with the request and a next that runs the next function or the static asset server.

    import { spool } from './spool';

    export const onRequest = (context: { request: Request; next(): Promise<Response> }) =>
      spool.handle(context.request, () => context.next());

    Hono

    Hono ignores the response a middleware returns once a route has answered, so assign it to c.res.

    import { Hono } from 'hono';
    import { page } from './routes';
    import { spool } from './spool';

    const app = new Hono();

    app.use('*', async (c, next) => {
      c.res = await spool.handle(c.req.raw, async () => {
        await next();
        return c.res;
      });
    });
    app.get('/node/:id', (c) => page(c.req.raw));

    export default app;

    Elysia

    onRequest answers the spool paths and returns nothing for the rest. The hook has to be an async function, because Elysia does not await a promise that a plain function returns.

    import { Elysia } from 'elysia';
    import { page } from './routes';
    import { spool } from './spool';

    export const app = new Elysia()
      .onRequest(async ({ request }) => {
        const { pathname } = new URL(request.url);
        return pathname === '/spool-sw.js' ? spool.stub() : await spool.respond(request);
      })
      .get('/node/:id', ({ request }) => spool.decorate(request, page(request)));

    itty-router

    Next.js route handlers return Response objects, so handle wraps one directly. The spool endpoints and the worker script go through the proxy, which returns undefined for every other request. Next.js 16 calls the file proxy.ts and the export proxy. Earlier versions call them middleware.ts and middleware. The proxy and the route handlers need the same shared store.

    Azure Functions

    An Azure v4 HTTP function takes an HttpRequest, which follows the Fetch standard, and returns an HttpResponseInit. Route every path to it with {*path}.

    import { app, type HttpRequest, type HttpResponseInit } from '@azure/functions';
    import { page } from './routes';
    import { spool } from './spool';

    export async function handler(request: HttpRequest): Promise<HttpResponseInit> {
      const hasBody = request.method !== 'GET' && request.method !== 'HEAD';
      const response = await spool.handle(
        new Request(request.url, {
          method: request.method,
          headers: [...request.headers],
          body: hasBody ? await request.arrayBuffer() : undefined
        }),
        page
      );
      return {
        status: response.status,
        headers: [...response.headers],
        body: await response.arrayBuffer()
      };
    }

    app.http('spool', {
      route: '{*path}',
      methods: ['GET', 'POST'],
      authLevel: 'anonymous',
      handler
    });

    Node

    toNodeListener turns a Fetch-style handler into a node:http listener. Its toRequest and writeResponse parts are what the frameworks below use to cross between Node and Fetch.

    Express

    Express responds through its own res, so it has no Fetch response to wrap. spool.respond answers /.spool/* and returns undefined for everything else, which sends the request on to the next Express handler. A route passes its page through spool.decorate to get the envelope and the script tag.

    import express from 'express';
    import { toNodeListener, toRequest, writeResponse } from '@drupflare/spool/node';
    import { page } from './routes';
    import { spool } from './spool';

    export const app = express();

    app.use(toNodeListener((request) => spool.respond(request)));
    app.get('/spool-sw.js', (req, res) => writeResponse(res, spool.stub()));
    app.get('/node/:id', async (req, res) => {
      const request = toRequest(req, res);
      await writeResponse(res, await spool.decorate(request, page(request)));
    });

    Fastify

    Fastify's reply.send takes a Fetch Response. An onRequest hook answers the spool paths from the raw request before Fastify reads the body.

    import Fastify from 'fastify';
    import { toRequest } from '@drupflare/spool/node';
    import { page } from './routes';
    import { spool } from './spool';

    export const app = Fastify();

    app.addHook('onRequest', async (req, reply) => {
      const response = await spool.respond(toRequest(req.raw, reply.raw));
      if (response) return reply.send(response);
    });
    app.get('/spool-sw.js', (req, reply) => reply.send(spool.stub()));
    app.get('/node/:id', async (req, reply) => {
      const request = toRequest(req.raw, reply.raw);
      return reply.send(await spool.decorate(request, page(request)));
    });

    Koa

    Koa exposes the Node objects as ctx.req and ctx.res. Setting ctx.respond to false stops Koa from writing a second response.

    import Koa from 'koa';
    import { toRequest, writeResponse } from '@drupflare/spool/node';
    import { page } from './routes';
    import { spool } from './spool';

    export const app = new Koa();

    app.use(async (ctx, next) => {
      const request = toRequest(ctx.req, ctx.res);
      const response = ctx.path === '/spool-sw.js' ? spool.stub() : await spool.respond(request);
      if (!response) return next();
      ctx.respond = false;
      await writeResponse(ctx.res, response);
    });
    app.use(async (ctx) => {
      if (!ctx.path.startsWith('/node/')) return;
      const request = toRequest(ctx.req, ctx.res);
      ctx.respond = false;
      await writeResponse(ctx.res, await spool.decorate(request, page(request)));
    });

    hapi

    hapi keeps the Node objects at request.raw. Returning h.abandon tells it the response is already written.

    import Hapi from '@hapi/hapi';
    import { toRequest, writeResponse } from '@drupflare/spool/node';
    import { page } from './routes';
    import { spool } from './spool';

    export const server = Hapi.server();

    server.ext('onRequest', async (request, h) => {
      const { req, res } = request.raw;
      const spoolRequest = toRequest(req, res);
      const response =
        request.path === '/spool-sw.js' ? spool.stub() : await spool.respond(spoolRequest);
      if (!response) return h.continue;
      await writeResponse(res, response);
      return h.abandon;
    });
    server.route({
      method: 'GET',
      path: '/node/{id}',
      handler: async (request, h) => {
        const { req, res } = request.raw;
        const spoolRequest = toRequest(req, res);
        await writeResponse(res, await spool.decorate(spoolRequest, page(spoolRequest)));
        return h.abandon;
      }
    });

    NestJS

    On the Express adapter, app.use takes spool's listener and a controller method that injects @Req() and @Res() writes the page. The example needs experimentalDecorators in tsconfig.json.

    🧱 Static Sites

    A site with no spool server can still answer repeat views from the device. It serves three files from one directory:

    • spool-sw.js, the worker, from a release or https://cdn.drupflare.com/spool/<version>/.
    • client.js, the page script, from the same place.
    • spool.json, the list of files the worker may keep.

    Each page loads the script with the tag from CDN Script, or from the site's own copy. The worker has no server to talk to, so it reads spool.json from the directory its own script sits in.

    {
      "schema": 1,
      "routes": [
        {
          "pattern": "/",
          "strategy": "static",
          "version": "sha256-<base64 digest of the page>",
          "freshness": { "maxStale": 3600, "mode": "soft" }
        },
        { "pattern": "/about", "strategy": "static", "version": "sha256-<base64 digest of the page>" },
        { "pattern": "/css/site.css", "strategy": "static", "version": "build-42" },
        {
          "pattern": "/client.js",
          "strategy": "static",
          "version": "sha384-<base64 digest of the file>"
        }
      ]
    }

    A route names one path, or a :name pattern whose paths share one version. version says what the file is now:

    • A sha256-, sha384- or sha512- value is checked against the bytes the worker fetched. A mismatch keeps nothing.
    • An entity tag such as "abc" is checked against the response's ETag.
    • Any other string is a label you change when the file changes.

    The first view of a path goes to the network, and the worker keeps a copy of the response as it arrives: the bytes and the headers, including any Content-Security-Policy. Later views of that path make no request until the route's maxStale passes, which defaults to 15 minutes. After that a soft route shows the copy and fetches spool.json once, and a hard route fetches it first. A file whose version changed, or whose route left the manifest, is dropped and the next view fetches it again. Set sync to deferred to wait for a request the page makes anyway, and offline to refuse to keep a hard route from showing a copy it cannot check.

    The worker keeps files up to 4 MiB and never a redirect or an error. It sends no analytics batches and makes no request to /.spool/*. Serve spool-sw.js with Cache-Control: max-age=86400; that header is what lets Chromium and Firefox skip the update check. To pin the script to the CDN, make /spool-sw.js a one-line file:

    importScripts('https://cdn.drupflare.com/spool/<version>/spool-sw.js');

    importScripts has no integrity check, so this form trusts the CDN host with the worker.

    🔀 Strategies

    A route is answered locally in one of five ways. A template route stores JSON and renders it through a compiled template. An assembly route stores a shell with named holes, fragment markup for the holes and values for named slots. A static route stores a file as the server sent it. A data route stores JSON and answers a GET for it. A projection route stores JSON and renders a page from it with a function your site bundles into its own worker.

    import { placeholder, slot } from '@drupflare/spool/protocol';
    import { defineRoute } from '@drupflare/spool/server';

    export const about = defineRoute('/about', {
      strategy: 'assembly',
      depends: () => ['menu'],
      load: () => ({
        shell: `<!doctype html><html><head><title>About</title></head><body>${placeholder('menu')}<main>Updated ${slot('updated')}</main></body></html>`,
        fragments: { menu: '<nav><a href="/">Home</a></nav>' },
        slots: { updated: '2026-10-19' }
      })
    });

    The worker leaves a hole it cannot fill in place and refuses to render a page with a gap, so the request goes to the network instead.

    A page the worker renders keeps the site's security headers. The worker remembers Content-Security-Policy (and its report-only form), X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy and the three Cross-Origin-* policies from the network answer to each path, and sends them with every local render of it. A path with no answer of its own uses the latest set from any navigation. A page with neither goes to the network until the worker has seen one, so a local view never goes out without the site's policy.

    Records and Projections

    Pages that read the same data share one stored copy. ctx.record(id, data) stores an authoritative value once under its id, and ctx.projection(id, data) stores a value derived from records. Both return a reference to put in the page's data. A record's id is its invalidation tag. Invalidating course:101 refreshes the records and projections that read it, and no others.

    import { defineRoute } from '@drupflare/spool/server';

    const courses: Record<string, string> = { '101': 'Intro', '102': 'Advanced' };

    export const course = defineRoute('/courses/:id', {
      strategy: 'template',
      template: {
        source: '<h1>{{title}}</h1><nav>{{#each menu}}<a>{{this}}</a>{{/each}}</nav>'
      },
      load: (ctx) => {
        const id = ctx.params['id'] ?? '';
        return {
          title: ctx.record(`course:${id}`, courses[id]),
          menu: ctx.projection(
            'menu',
            Object.keys(courses).map((key) => ctx.record(`course:${key}`, courses[key]))
          )
        };
      }
    });

    The server sends only the records and projections the device does not already hold at a current version. A sync for the next page transfers the entries that page reads and that changed.

    Templates

    Templates use Mustache-shaped syntax with no expressions, so the worker needs no eval.

    Syntax Meaning
    {{field}} the field, HTML-escaped; a.b reaches into objects
    {{{field}}} the field as markup; allowed only for names in trusted
    {{#each list}}...{{/each}} repeats for each item; {{this}} and {{@index}} work
    {{#if field}}...{{else}}...{{/if}} renders a branch on whether the field is truthy
    {{! note }} a comment that renders nothing 
    import { defineRoute } from '@drupflare/spool/server';

    export const news = defineRoute('/news/:slug', {
      strategy: 'template',
      template: {
        source:
          '<article><h1>{{title}}</h1>{{#if byline}}<p>{{byline}}</p>{{else}}<p>Staff</p>{{/if}}<div>{{{body}}}</div><ul>{{#each tags}}<li>{{@index}} {{this}}</li>{{/each}}</ul></article>',
        trusted: ['body']
      },
      depends: (ctx) => [`news:${ctx.params['slug']}`],
      load: () => ({
        title: 'Hello',
        byline: null,
        body: '<p>Trusted markup</p>',
        tags: ['a', 'b']
      })
    });

    A template that names a field it does not trust for markup fails when the route is declared.

    A public template route can carry its own data in the page. inlineMaxBytes on createSpool sets the largest artifact, in bytes, that handle and decorate write into the HTML as an escaped <script type="application/spool+json"> element. The worker reads it from the response and skips the /.spool/artifact request. It is 0, which is off, because every network view of the page carries the element, used or not. The page the visitor sees and the shadow comparison ignore it.

    Static Files

    A static route has no load and no template. The application serves the file as it always did, and handle or decorate marks the response for the worker, which keeps the bytes. A tag in depends ties the file to a deploy, and spool.invalidate after one makes devices fetch the file again. A static route is always public and is always answered from the device, so it takes no scope, persist or mode. A query string makes a different file: /app.js?v=2 is not answered with the copy of /app.js, and a query the worker has not stored goes to the network.

    import { defineRoute } from '@drupflare/spool/server';

    export const about = defineRoute('/about', {
      strategy: 'static',
      depends: () => ['site'],
      freshness: { maxStale: 3600, mode: 'soft' }
    });

    Projection and Data Routes

    A data route answers a GET for JSON, such as an API read, from the stored value, so the page's fetch makes no request. The worker answers with JSON.stringify of what load returned, which means the application's own handler has to return the same JSON. A navigation to the URL still goes to the network.

    A projection route needs a renderer. Spool ships no bundler: write a worker with serve from @drupflare/spool/sw, bundle it with your own toolchain, and pass the bundle to createSpool as worker. The server puts the config in front of your bundle as self.__SPOOL_CONFIG__, and spool.config is the same object as JSON if you would rather inline it at build time. A route with no renderer is refused by the worker and the network answers.

    import { defineRoute } from '@drupflare/spool/server';

    export const course = defineRoute('/api/courses/:id', {
      strategy: 'data',
      depends: (ctx) => [`course:${ctx.params['id']}`],
      load: (ctx) => ({ id: ctx.params['id'], title: 'Intro' }),
      provision: { reuse: 0.8, futureViews: 6 }
    });

    export const roster = defineRoute('/rosters/:id', {
      strategy: 'projection',
      depends: (ctx) => [`roster:${ctx.params['id']}`],
      load: (ctx) => ({ id: ctx.params['id'], names: ['Ada', 'Bo'] })
    });

    import { escapeHtml } from '@drupflare/spool/protocol';
    import { serve } from '@drupflare/spool/sw';

    declare const CONFIG: string;

    serve(JSON.parse(CONFIG), {
      '/rosters/:id': (artifact) => {
        const { names } = (artifact.body as { data: { names: string[] } }).data;
        return `<!doctype html><html><head><title>Roster</title></head><body><ul>${names.map((name) => `<li>${escapeHtml(name)}</li>`).join('')}</ul></body></html>`;
      }
    });

    The server also decides whether to send an artifact at all. It weighs the bytes it would send, records included, against what a local view saves: reuse times future views times the bytes a view avoids, less the cost of the request. When that is not positive it answers 204 with Spool-Provision: declined, and the worker leaves that path to the network until it restarts. The priors are scenario assumptions: set them from your own telemetry in provision, or per route as above. A data route weighs against its own size, so its reuse times future views must exceed one. The defaults of 0.5 and 2 give exactly one, which breaks even, and the route is left out.

    Query Routes

    A URL with a query string goes to the network. A public template, projection or data route can declare the query strings it answers, and the device then answers a new filter, sort or page of a collection it already holds with no request.

    import { datasetProof, defineRoute } from '@drupflare/spool/server';

    const people = [
      { name: 'Ada', department: 'math', age: 36 },
      { name: 'Bo', department: 'cs', age: 25 }
    ];

    export const directory = defineRoute('/people', {
      strategy: 'template',
      template: {
        source:
          '<h1>{{#if query}}Page {{query.page}} of {{query.pages}}{{else}}Everyone{{/if}}</h1><ul>{{#each people}}<li>{{name}}</li>{{/each}}</ul>'
      },
      depends: () => ['people'],
      load: async () => ({ people, proof: await datasetProof(people) }),
      query: {
        list: 'people',
        filter: { department: 'string', age: 'number' },
        sort: ['name', 'age'],
        pageSize: 20
      },
      provision: { reuse: 0.8, futureViews: 6 }
    });

    list names the key of the loaded data that holds the whole collection, an array of flat objects. Each key of filter is a query parameter that keeps the items whose field of the same name equals it, read as a string or a number. A repeated parameter matches any of its values, and different parameters combine with and. sort lists the fields the sort parameter may name, and -name sorts descending. Ties keep the stored order. Strings compare by UTF-16 code unit, with no locale and no case folding, so the application's own sort has to agree. A database that compares bytes, such as SQLite by default, agrees except for characters above U+FFFF, and a case-insensitive or locale collation does not. pageSize sets the items per page and page counts from 1; without it the route is one page of everything. A route with principal scope, or any other strategy, cannot declare query.

    load returns the array at list and a proof made by datasetProof. The server refuses to build the artifact when the proof is missing or does not match the array. The worker computes the proof again from the stored copy before it answers a query. The proof shows that the device holds the array the server sent. That the array is the whole collection is the route's declaration: list has to hold every item the application's own answer could draw from, or a filter returns fewer rows than the server would.

    The template, or the renderer of a projection route, receives the stored data with the array replaced by the page's items and one added key, query, holding { total, page, pages }. total counts the items after filtering. A data route answers with that same object as JSON. The URL without a query string renders the stored data as it is and has no query key, which is what {{#if query}} tests above.

    The worker answers locally only when the artifact for the path is held and fresh under the route's freshness contract, the proof matches and the query is one the route declares. Everything else goes to the network as before: a parameter the route does not name, a number filter that is not a finite number, a sort given twice or not listed, a page that is not a positive integer or lies past the last page, and an item that is not an object. A copy that fails its proof is dropped and fetched whole again. The worker never stores anything under a URL with a query string, and in shadow mode it compares its render with the network answer for the same URL.

    A query route's artifact is the whole collection, so it is large. The provisioning rule weighs it like any other artifact, and provision on the route sets the priors. A collection repays its transfer after entryBreakEven(bytes, documentBytes) local answers per device: a 40 KB collection that replaces 17 KB documents needs 2.3 (L2). Pages of one visit come from one held copy until a sync replaces it, so paging never mixes two versions on a device.

    ⏳ Freshness Contracts

    Each route declares how long a stored page may go without validation. maxStale is in seconds.

    • hard: once maxStale passes, the worker validates the page with the server before it shows it. Offline, the route's offline rule decides.
    • soft: the worker shows the stored page at once and syncs afterward. A soft bound is a stale-while-revalidate window and promises nothing about how fresh the shown page is.

    Public routes default to 15 minutes soft, and routes with scope: 'principal' to five minutes hard; Authenticated Data covers how their pages are stored. offline defaults to serve for public routes and refuse for principal routes. A soft route may set sync: 'deferred' to queue its refresh for the next network request that happens anyway.

    import { defineRoute } from '@drupflare/spool/server';

    export const stock = defineRoute('/stock/:sku', {
      strategy: 'template',
      template: { source: '<p>{{sku}}: {{count}}</p>' },
      depends: (ctx) => [`stock:${ctx.params['sku']}`],
      load: (ctx) => ({ sku: ctx.params['sku'], count: 3 }),
      freshness: { maxStale: 60, mode: 'hard' },
      offline: 'refuse'
    });

    export const notice = defineRoute('/notices/:id', {
      strategy: 'template',
      template: { source: '<p>{{text}}</p>' },
      depends: (ctx) => [`notice:${ctx.params['id']}`],
      load: () => ({ text: 'Closed on Friday' }),
      freshness: { maxStale: 3600, mode: 'soft' },
      sync: 'deferred'
    });

    The worker syncs the smallest set of changed dependencies the next page needs. One worker leads the sync for every tab of an origin. A response to a request that happens anyway can carry invalidations, so a sync does not always need a request of its own.

    🔐 Authenticated Data

    Set scope: 'principal' on a route that depends on who is signed in, and give createSpool an identity option. The server sends Spool-Partition, an HMAC of the principal under your secret, so the browser can tell users apart without learning who they are. The worker keeps each partition in its own IndexedDB database with the artifacts, records, projections and sync state sealed with AES-GCM. Each value is bound to its partition, kind and id, so a row copied into another slot does not decrypt.

    retention picks the key. persistent is a non-extractable key in IndexedDB that survives a restart and is deleted on logout or a change of partition. session, the default, is a key held in the worker's memory, which the browser discards when it stops the worker. Deleting a key makes what it sealed unreadable, which is crypto-shredding of data at rest. It does not protect against script running on your origin, which can ask the worker for whatever the page can. The ids and versions that serve as storage keys stay readable, so use opaque ids for anything sensitive.

    A principal route defaults to a five-minute hard bound and offline: 'refuse'. Revocation rides the same bound: tag a page with the permission it needs, call spool.invalidate when the permission goes, and the first required sync past the bound finds the page invalid.

    A different Spool-Partition wipes the partition before it. A login or account-switch handler has to send the new value itself with spool.partition(principal), because the request it answers still carries the old identity. A sync answer carries Spool-Partition for the request's identity too, so a sign-in the worker never saw ends at the first required sync, no later than the route's maxStale plus the next view. Paths in logout are wiped when the request reaches the worker, before it is sent, so logout empties every tab even with the network down. The worker first sends the same-origin posts it holds in beacons, while they still carry the session that is ending, and drops any that do not get through. The page runtime dispatches a spool:cleared event on window in every tab when that happens, so a page can blank what it shows. A response can also send Spool-Clear: * wipes everything, a partition id wipes one. decorate(request, response, { clear: ['*'], hardReset: true }) adds Clear-Site-Data: "storage" as well, the browser's own reset of everything the origin holds, service worker included. Its Safari support is unverified, so rely on the worker's wipe.

    import { createSpool, defineRoute } from '@drupflare/spool/server';
    import { memoryStore } from '@drupflare/spool/stores';

    export const grades = defineRoute('/grades', {
      strategy: 'template',
      scope: 'principal',
      retention: 'persistent',
      template: { source: '<h1>Grades for {{owner}}</h1>' },
      depends: (ctx) => [`perm:${ctx.identity?.principal}`, `grades:${ctx.identity?.principal}`],
      load: (ctx) => ({ owner: ctx.identity?.principal })
    });

    export const spool = createSpool({
      routes: [grades],
      store: memoryStore(),
      identity: {
        secret: 'a long random value kept on the server',
        resolve: (request) => {
          const user = /user=(\w+)/.exec(request.headers.get('cookie') ?? '')?.[1];
          return user ? { principal: user } : null;
        }
      },
      logout: ['/logout']
    });

    export async function login(user: string): Promise<Response> {
      return new Response('Signed in', {
        headers: {
          'set-cookie': `user=${user}; Path=/`,
          'spool-partition': await spool.partition(user)
        }
      });
    }

    A sync that asks for everything changed lists the tags of every change, so tags for principal data should be opaque too. The worker syncs a principal page with need, which names only the tags that page reads.

    📚 Catalogue

    A catalogue sends the data of pages a visitor may open next, so that opening one makes no request. An entry costs its bytes whether or not the page is opened, and an opened one saves a document request, so an entry pays only when enough visitors open it. The break-even share is k * E / (k * D + o), where E is the entry's compressed bytes, D the bytes of the document it replaces, k the joules to move a byte and o the origin request a view avoids. An entry the size of the document needs 96% of visitors to open it, which no page gets. An entry that is only the data for a template the device already holds is a few hundred bytes to a few kilobytes and pays at a few percent. On the payload reading, the rendered fields of a node were a median 473 bytes compressed on 19 pages from two sites (L1, measurements/payload), against a document of about 17,000 bytes. References such as media and terms are left out of that figure, so a real entry is larger. An entry is data for a template, projection or data route and never HTML.

    The site supplies the candidates. A route's catalogue returns the pages a visitor on it may open next, each with the share expected to. Take the share from your own nextShare over the sink (each spool.view names the route the visitor came from), from link position, or from a fixed prior. Pass { first: true } to nextShare to count only first views, which is what an entry saves: the share over all views ran 1.5 to 7 times high in the bins that decide an entry in a replay of public visitors (docs/impact.md). documentBytes on the entry's route says what a hit saves, and the provisioning prior is used when it is absent.

    A share taken from counts can carry n, the observations behind it. catalogueConfidence on createSpool is a number of standard deviations, and with it above 0 an entry whose guess has an n is judged on the lower confidence bound of its p, so a share seen on 5 visits stops counting as one seen on 5,000. It defaults to 0, which judges every guess on its p. NavModel in @drupflare/spool/protocol keeps first-order counts with decay and a prior and returns a p with the weight to pass as n. In a replay of 989,818 public visitors, a model like that earned more per provisioned kilobyte than the most popular page (docs/impact.md).

    import { createSpool, defineRoute } from '@drupflare/spool/server';
    import { memoryStore } from '@drupflare/spool/stores';

    export const home = defineRoute('/', {
      strategy: 'template',
      template: { source: '<h1>Courses</h1>' },
      load: () => ({}),
      catalogue: () => [
        { path: '/courses/101', p: 0.3 },
        { path: '/courses/102', p: 0.1 }
      ]
    });

    export const course = defineRoute('/courses/:id', {
      strategy: 'template',
      template: { source: '<h1>{{title}}</h1>' },
      depends: (ctx) => [`course:${ctx.params['id']}`],
      load: (ctx) => ({ title: `Course ${ctx.params['id']}` }),
      documentBytes: 17_000
    });

    export const spool = createSpool({
      routes: [home, course],
      store: memoryStore(),
      catalogueBytes: 16_384
    });

    The server sends an entry only when its share reaches its own break-even, best expected net first, until catalogueBytes is spent. The cap counts compressed bytes and defaults to 32 KiB. It builds at most 32 pages for one request, measures each entry with Brotli where the runtime has it and gzip where it does not, and skips a static or assembly route. A request with Save-Data: on gets no entries.

    The ask rides the beacon batch the worker already sends. A due ask also makes the next network moment send that batch, when a view is held to carry it, so a visit of two or three pages gets its entries without waiting for 20 views or an hour. That costs one POST /.spool/beacon for each catalogue page, device and day, sent at a request that happens anyway. A local view never sends it, and a moment with nothing held sends nothing. The worker stores the entries like provisioned pages, and the first view of an unopened one is reported with the reason catalogue. catalogueFigures reads the views and the worker's ledger for the entries sent and used, the hit share, and the bytes sent against the bytes saved. Until shadow views measure the shares, the saving is a scenario.

    A hit saves the document request and nothing else. On the Drupal pages measured (75 first views of internal pages on 10 sites, L1, measurements/trim), a view of a page still fetched that page's new images and stylesheet and script aggregates: only 3% of those first views moved nothing but the document. A catalogue view takes the document off the wire, and the rest of the page is the site's own HTTP cache and asset trimming.

    A principal route can be an entry. The worker then names every catalogue entry no page has opened at each sync of a principal page, so a revoked one is dropped at the first required sync. The request that asks for a catalogue names the path of the page the visitor is on, including one the worker showed locally, so a route that should not tell the server leaves catalogue off. docs/security.md covers both.

    📡 Analytics Batching

    A page that keeps analytics scripts posting to an endpoint makes a request on every view, which defeats a local view. List the same-origin POST paths in beacons. The worker answers each post with a 204 and queues it in IndexedDB. At the next network request that happens anyway it sends the post to the URL the page meant, with its method, content type, query and body, so the vendor receives what the page sent. Spool's own events go to /.spool/beacon in one batch, where a sink receives them. A held post goes out on its own at most once every 24 hours, when the oldest is a day old. A body over 64 KiB, counted in bytes, or a binary body goes to the network at once. Firefox does not route fetch calls made with keepalive: true through the worker, so a script that posts that way is not queued there.

    import { createSpool, jsonLinesSink } from '@drupflare/spool/server';
    import { memoryStore } from '@drupflare/spool/stores';
    import { routes } from './routes';

    export const spool = createSpool({
      routes,
      store: memoryStore(),
      beacons: ['/cdn-cgi/rum'],
      sink: jsonLinesSink((line) => console.log(line))
    });

    jsonLinesSink writes one JSON line per event. analyticsEngineSink writes to a Workers Analytics Engine dataset, splitting a long body across data points so nothing is cut off, and memorySink keeps events for tests. The worker also queues one spool.view event per page view with the tier, the reason, the staleness and the route the visitor came from (a pattern or external, never a URL). viewsOf reads those events back. Set views: false to turn that off. workSeries records how long each route's handler took, for peak-work reports.

    Collectors

    A collectors entry holds requests to another origin, such as an analytics host. The page gets an empty answer at once and the request leaves at a network moment, inside maxAgeMs. An event past the cap is dropped, never sent late, and each drop is counted and written to the sink as /.spool/dropped. With delivery: 'replay' the worker sends the held request to the vendor with no cookies, so identity has to be in the payload, and stamp writes the event's time into a query parameter for a vendor that takes one. With delivery: 'sink' the server half forwards it.

    GA4's browser collector takes no backdating. The Measurement Protocol accepts events with their own timestamps up to 72 hours old and wants them within 48 hours to attribute them, and it needs an API secret the page must not hold. GA4_COLLECTOR holds the g/collect hit for 48 hours and ga4Sink sends it as a Measurement Protocol request carrying the original timestamp_micros. ga4Sink checks its requests against the rules spool knows (mpViolations); set debug: true to send them to /debug/mp/collect with your own measurement id and secret. Spool holds events whether or not the visitor consented, so gate the analytics tag itself, and ask your counsel whether holding an event in IndexedDB needs consent where you operate. Programmatic ads are never held, replayed or answered locally.

    import { GA4_COLLECTOR } from '@drupflare/spool/protocol';
    import { combineSinks, createSpool, ga4Sink, jsonLinesSink } from '@drupflare/spool/server';
    import { memoryStore } from '@drupflare/spool/stores';
    import { routes } from './routes';

    export const spool = createSpool({
      routes,
      store: memoryStore(),
      collectors: [
        GA4_COLLECTOR,
        {
          vendor: 'matomo',
          match: 'https://stats.example.edu/matomo.php',
          maxAgeMs: 23 * 3_600_000,
          delivery: 'replay',
          stamp: { param: 'cdt', kind: 'datetime-utc' }
        }
      ],
      sink: combineSinks(
        jsonLinesSink((line) => console.log(line)),
        ga4Sink({ measurementId: 'G-XXXXXXXXXX', apiSecret: 'kept on the server' })
      )
    });

    🧷 Third-Party Files

    A view that loads a file from another origin is not zero-network. The page reports, when it is hidden, how many cross-origin resources it loaded and from which origins (origins only, never paths). thirdPartyReport reads those reports from viewsOf and ranks the origins by the views each one alone blocks, with a class and a remedy from a short table you can replace. The counts are an upper bound on network requests, since a cross-origin timing entry says nothing about cache hits without Timing-Allow-Origin.

    The opt-in thirdParty cache removes the request for files that name their own bytes. List the origins in allow. The worker learns a file from the first view and keeps it only when the URL carries a hash, a version or a /v12/ segment, or the origin marks it immutable. A file versioned only by a query parameter is checked again at a network moment once it is a day old. It keeps nothing else, and nothing it cannot read: an opaque response counts about 7 MB against quota in Chromium, so allowOpaque is off by default. WebKit does not send font requests from a stylesheet through the worker, so fonts stay on the network there.

    import { thirdPartyReport } from '@drupflare/spool/report';
    import { createSpool, memorySink, viewsOf } from '@drupflare/spool/server';
    import { memoryStore } from '@drupflare/spool/stores';
    import { routes } from './routes';

    const sink = memorySink();

    export const spool = createSpool({
      routes,
      store: memoryStore(),
      sink,
      thirdParty: {
        allow: ['https://fonts.gstatic.com', 'https://cdn.example.edu'],
        maxEntries: 32
      }
    });

    export const report = () => thirdPartyReport(viewsOf(sink.events));

    ⚡ Subresource Handling

    By default the worker answers an immutable same-origin asset from CacheStorage. assets changes that. passthrough leaves assets to the browser's cache and never touches them. static-routing asks the browser through InstallEvent.addRoutes to send only navigations, beacons and routed paths to the worker and the rest of the origin to the network, and acts as passthrough where the API does not exist: Chromium has it, Playwright's WebKit has it on macOS and not on Linux, and Firefox does not. Both options cut the service worker's fetch events (Static Routing took them from 32 to 3 per view on a desktop Chromium rig); neither changes server-side Worker invocations. Neither is measured to save energy. In the same run, new-tab views drew 2.78 J, 2.83 J and 2.84 J of RAPL package energy above idle with CacheStorage, navigation-only handling and Static Routing (8 rounds each), and the ranges overlap. Under Static Routing a same-origin write no longer reaches the worker, so it is not a network moment and its response cannot carry invalidations; navigations still are.

    import { createSpool } from '@drupflare/spool/server';
    import { memoryStore } from '@drupflare/spool/stores';
    import { routes } from './routes';

    export const spool = createSpool({
      routes,
      store: memoryStore(),
      assets: 'static-routing'
    });

    🔍 Shadow Mode

    In shadow mode the worker decides whether it could serve a page locally, renders it, still fetches the page from the server, compares the two with normalise and reports the result. It never serves the local page. Use it to measure eligibility and mismatches on real traffic before turning serving on. A static route has no shadow comparison.

    import { createSpool } from '@drupflare/spool/server';
    import { memoryStore } from '@drupflare/spool/stores';
    import { routes } from './routes';

    export const shadowed = createSpool({ routes, store: memoryStore(), mode: 'shadow' });
    export const canary = createSpool({ routes, store: memoryStore(), shadowSample: 0.05 });

    mode: 'shadow' applies to every route that does not name its own mode. shadowSample keeps a share of views in shadow while the rest are served, which gives a standing canary. A mismatch names its route, so a route whose template and application disagree shows up before a visitor sees it. The worker records the shadow comparison for navigations only. Subresources and other requests keep the browser's own path.

    🔌 Proxy Mode

    spoolProxy fronts an origin that cannot load the library, such as PHP, Drupal with no module, or anything else that speaks HTTP. It returns a Fetch handler. The proxy answers /.spool/* and /spool-sw.js. Every other request goes to the origin with its method, headers and body, and a redirect is passed on, not followed. A page the proxy may keep is decorated like a createSpool response, so the worker stores it and answers later views with no request. A cold visit costs one origin fetch: the proxy names a hash of the page in Spool-Artifact, and the worker keeps the page it already received as the artifact when its own hash matches. On any mismatch it asks /.spool/artifact as before. In the first-payload reading (L1, a synthetic 11,145-byte page) a cold visit made 1 request and 1 origin fetch where it made 2 and 2 before.

    spool takes the options createSpool takes, minus routes. The proxy adds one public assembly route that matches every path (/**) and uses the origin's finished HTML as the artifact. routes lists overrides, such as a shorter freshness bound for one pattern. They match first and take the same fields as defineRoute, without load.

    On Node the handler goes through toNodeListener. origin is the address of the real server and has no path.

    import { createServer } from 'node:http';
    import { toNodeListener } from '@drupflare/spool/node';
    import { spoolProxy } from '@drupflare/spool/proxy';
    import { memoryStore } from '@drupflare/spool/stores';

    const proxy = spoolProxy({
      origin: process.env['ORIGIN'] as string,
      spool: { store: memoryStore() },
      purgeSecret: process.env['PURGE_SECRET']
    });

    export const server = createServer(toNodeListener(proxy));

    On Workers the proxy is built once per isolate and keeps the version vector in a Durable Object, bound as in Cloudflare Workers. Set the purge secret with wrangler secret put PURGE_SECRET.

    import { spoolProxy, type SpoolProxy } from '@drupflare/spool/proxy';
    import { durableObjectStore } from '@drupflare/spool/stores/durable-object';

    export { SpoolVersions } from '@drupflare/spool/stores/durable-object';

    let proxy: SpoolProxy | undefined;

    export default {
      fetch(request: Request, env: Cloudflare.Env) {
        proxy ??= spoolProxy({
          origin: 'https://origin.example.edu',
          spool: { store: durableObjectStore(env.SPOOL_VERSIONS) },
          purgeSecret: env.PURGE_SECRET
        });
        return proxy(request);
      }
    };

    Tags

    The tags the origin sends become the page's dependencies. The proxy reads Cache-Tag (comma separated), Surrogate-Key and X-Drupal-Cache-Tags (space separated) and xkey (spaces or commas), then removes them from the response unless exposeTags is true. A page with no tags depends on one tag derived from its path.

    Eligibility

    The proxy keeps a response only when all of these hold:

    • the request is a GET or HEAD, has no query string and no Authorization header, and carries no cookie outside publicCookies, which is empty by default
    • the response is a 200 text/html, or the answer of a data route
    • the page is UTF-8, or declares no charset in its Content-Type or in a <meta> within its first 1024 bytes
    • the response sets no cookie outside publicCookies, has no private or no-store in Cache-Control, a Vary that names only Accept-Encoding and Cookie, no more than maxTags tags and no more than maxBytes bytes

    Everything else is forwarded untouched. A page the proxy declines tells the worker to drop its copy of that path, and a response that sets a cookie outside publicCookies tells the worker to clear everything it holds, so a login leaves no anonymous copy to show. Put cookies that carry no identity on the list, such as a bot-check or load-balancer cookie set on every response; otherwise proxy mode never keeps a page on that site. Writes always go to the origin and are never answered locally.

    Principal routes are off unless spool.identity is set. With it, a route declared scope: 'principal' follows the partitions in Authenticated Data. The cookie, Authorization and private rules do not apply to it. Set-Cookie and no-store still do.

    Invalidation

    Two signals reach the proxy. When a page it forwards differs from the last body it saw, it bumps that page's tags. The proxy hashes the body after normalise, and ignore takes patterns to blank, such as a per-render form token. POST /.spool/purge bumps the tags it is given, so a CMS hook or Drupal's purge module can call it. It needs Authorization: Bearer <purgeSecret> and a JSON body, and it refuses every call when no secret is set.

    curl -X POST https://example.edu/.spool/purge \
      -H "Authorization: Bearer $PURGE_SECRET" \
      -H "Content-Type: application/json" \
      -d '{"tags": ["node:1", "config:system.menu.main"]}'

    Limits

    The proxy sees finished HTML, not the database behind it. An artifact is a whole page, the replica holds no records, and two pages never share a fragment. A page stays on a device until its route's maxStale passes and the next sync reports a change, so freshness is bounded by maxStale plus the time a purge takes to arrive.

    A tag shared by many pages invalidates all of them when one changes. The remembered bodies live in the instance: a restart forgets them, and each instance of a scaled-out proxy keeps its own. A whole page is a large artifact, and the provisioning rule declines one that costs more than the priors say it saves, so set provision on the spool for large pages. A Content-Security-Policy that allows only nonce or hash scripts blocks the injected client tag. A URL with a query string always goes to the origin, because the proxy holds finished HTML and has no collection to filter; Query Routes apply to createSpool only. Trimmed Stylesheets covers the trim option and Images and Video the images and video options.

    🧹 Trimmed Stylesheets

    A new page of a Drupal site usually loads a stylesheet aggregate the visitor has not seen, and most of its rules match nothing on the page. @drupflare/spool/trim builds a manifest that removes the rules no page of the site can match, and spoolProxy serves the trimmed text in place of the origin's file. Each file is trimmed against every page and script of the site, never against one page, so it keeps its URL and its one cached copy. Rules are only removed, so the cascade of what stays is unchanged.

    import { spoolProxy } from '@drupflare/spool/proxy';
    import { memoryStore } from '@drupflare/spool/stores';
    import { buildTrimManifest } from '@drupflare/spool/trim';

    export const manifest = await buildTrimManifest({
      pages: ['<body class="hero"><a class="button">Apply</a></body>'],
      scripts: [{ url: '/js/site.js', text: 'menu.classList.add("open")' }],
      styles: [{ url: '/css/site.css', text: '.hero{a:b}.button{c:d}.open{e:f}.print-only{g:h}' }]
    });

    export const proxy = spoolProxy({
      origin: 'https://origin.example.edu',
      spool: { store: memoryStore() },
      trim: manifest
    });

    pages is HTML, scripts and styles are the same-origin files the pages load, and url is the address the page links. Crawl with a browser and pass the page's DOM after load and after a scroll as well as the origin's HTML: a class that a script builds from parts, such as 'fs-carousel' + '-enabled', is only in the rendered page. Pass the scripts of other origins that the pages load as foreignScripts, since a widget that builds markup adds classes too.

    Two checks protect a visitor. The proxy serves a trimmed file only when the origin's bytes still hash to the manifest's source, and otherwise sends the origin's file and counts a mismatch. It also reads every HTML page before it leaves: a page with a token the trim removed a rule for, or a same-origin script the manifest was not built with, links the full file through spool-trim=0. proxy.trim counts the files served, the mismatches and the guard firings, and the sink gets each mismatch and firing as an event. docs/security.md names what the guard cannot see: a class a vendor script adds after the crawl, markup injected after load from a page the crawl never requested, and a class name built at runtime that no crawl rendered.

    The proxy trims CSS and leaves JavaScript alone. Coverage at load cannot see what a click or a scroll will need: the used share of same-origin JavaScript rose from 36% at load to 40% after one scroll on the pages measured (L1), so no load-time figure says which of the rest is dead. The same saving from a build step that runs PurgeCSS with a safelist needs no proxy. The proxy gets it without a change to the origin. The saving applies to a network view of a page the visitor has not seen, never to a repeat or local view, and it is not part of the per-view headline; docs/impact.md has the bytes, joules and prices.

    🎬 Images and Video

    A browser that has fetched an image cannot make it smaller, so conversion happens where the file is served. @drupflare/spool/media gives spoolProxy three options, each off until set. images converts a JPEG or PNG response to WebP for a browser whose Accept lists it. video rewrites the <video> tags of an HTML response, such as adding preload="none". embeds swaps a YouTube or Vimeo iframe for a link that loads the player on click.

    import { type ImageEncoder } from '@drupflare/spool/media';
    import { spoolProxy } from '@drupflare/spool/proxy';
    import { memoryStore } from '@drupflare/spool/stores';

    export function mediaProxy(encoder: ImageEncoder) {
      return spoolProxy({
        origin: 'https://origin.example.edu',
        spool: { store: memoryStore() },
        images: { encoder, width: { fallback: 1600 } },
        video: { preload: 'none', autoplay: 'defer', when: 'slow' }
      });
    }

    An ImageEncoder takes the origin's bytes and { format: 'webp', quality, width } and returns { bytes }. It never upscales, so width is a ceiling, and it throws on input it cannot decode. spool has no runtime dependencies and ships an adapter for tinyimg, which decodes and encodes inside WebAssembly:

    import { readFile } from 'node:fs/promises';
    import { TinyImgModule, transform } from '@gmitch215/tinyimg';
    import { tinyimgEncoder } from '@drupflare/spool/media';

    const wasm = new URL(import.meta.resolve('@gmitch215/tinyimg/tinyimg.wasm'));
    const module = await TinyImgModule.loadBytes(await readFile(wasm));

    export const encoder = tinyimgEncoder({ module, transform });

    Use tinyimg 1.1.1 or later. Version 1.1.0 and earlier drop the EXIF orientation tag without rotating the pixels, so a phone photo comes out sideways. tinyimgEncoder throws when the module reports an older version.

    Quality is 80, 65 for Save-Data: on and 70 for an ECT of slow-2g, 2g or 3g. The width comes from Sec-CH-Width, then Sec-CH-Viewport-Width times Sec-CH-DPR, then width.fallback. The proxy converts a GET that matches paths (JPEG and PNG names by default), has no Range or Authorization, and gets a 200 JPEG or PNG without a cookie between minBytes (4096) and maxBytes (15,000,000). Anything else, and any file the encoder cannot shrink, goes out as the origin sent it. The proxy fetches the origin for every request, so a visitor only gets bytes the origin sent that visitor.

    A converted response carries Vary for Accept, Save-Data, Sec-CH-Width, Sec-CH-DPR, Sec-CH-Viewport-Width and ECT, a weak ETag and X-Spool-Image. HTML responses gain Accept-CH for the three size hints and ECT unless hints is false, and the browser then sends them with later image requests to the same origin.

    maxWidth (2560) is the width for a request that carries no hint, and false removes it. png is 'lossy' by default. 'lossless' encodes every PNG without loss, and 'auto' encodes a PNG under 200 KB both ways and serves the smaller file, which suits screenshots and flat graphics. Requests for the same file, quality and width share one encoder call while it runs. The proxy waits timeoutMs (10,000) for the encoder and then serves the origin's file, and the late result is cached for the next request. timeoutMs: false waits without limit.

    Drupal's video formatter has no preload setting, and preload="none" does not stop autoplay. autoplay: 'defer' removes the attribute, adds controls and marks the tag data-spool-autoplay. With when: 'always' the page the spool keeps carries the rewrite. With 'save-data' or 'slow' the rewritten page is private to that visitor: it gets private in Cache-Control and Save-Data, ECT in Vary, and the spool does not keep it. A device's stored copy of that page keeps the origin's tags.

    proxy.images counts converted, bytesIn and bytesOut (converted responses only), cacheHits, coalesced, lazied, responsive, and skipped by reason. proxy.video counts pages and rewritten. Read the saving as bytesIn - bytesOut over real traffic on the site. A request for any other path counts under skipped.path, so that key follows total traffic. docs/security.md covers the decoder.

    Page Rewrites

    Three options change the HTML the origin sends. Each edits start tags only and leaves every other byte as it was, and a rewritten page gets a weak ETag.

    import { type ImageEncoder } from '@drupflare/spool/media';
    import { spoolProxy } from '@drupflare/spool/proxy';
    import { memoryStore } from '@drupflare/spool/stores';

    export function rewriteProxy(encoder: ImageEncoder) {
      return spoolProxy({
        origin: 'https://origin.example.edu',
        spool: { store: memoryStore() },
        images: {
          encoder,
          png: 'auto',
          maxWidth: 1920,
          timeoutMs: 5000,
          lazy: { skip: 3 },
          responsive: { widths: [480, 960, 1440], sizes: '(min-width: 60em) 50vw, 100vw' }
        },
        embeds: { providers: ['youtube'], thumbnail: false }
      });
    }

    lazy adds loading="lazy" and decoding="async" to each <img> after the first skip (2 by default), and iframes: true does the same for <iframe>. It leaves a tag that has loading, fetchpriority or a lazy-loading library's data-src, a tag inside a <header> or <noscript>, and an image that a <link rel="preload" as="image"> names. A browser that defers the largest image of a page paints it later, so skip is the only guard and the option is off until set. In a crawl of 70 pages per profile on 16 sites, the default skip of 2 made the largest image lazy on 2 of 23 desktop pages and 2 of 20 phone pages that had an image as their largest element, and no skip from 2 to 4 reached zero on both profiles.

    responsive adds a srcset of ?spool-w=<width> variants to a same-origin <img> that has none, one per entry of widths (320, 480, 640, 960, 1280 and 1920 by default), and a sizes of 100vw unless the tag has one. The proxy removes spool-w before it asks the origin, answers only widths from the list and never sends a file larger than the origin's. Firefox and Safari send no Sec-CH-Width, and this is how they get a resized file. Name the layout width in sizes, since 100vw makes the browser pick the widest candidate it can use. A tag with srcset or data-src, and any tag inside <picture>, stays as it is.

    embeds replaces a server-rendered YouTube or Vimeo <iframe> with one whose srcdoc holds a link to the player. YouTube shows its thumbnail (thumbnail: false shows a plain frame) and the player loads on click. A page that sends Content-Security-Policy is left alone unless ignoreCsp is true, and so is an embed with enablejsapi=1. An embed that plays on its own by design stays too: a URL with background=1, or with autoplay=1 beside mute, muted or loop, and an iframe whose class or id names a hero, ambient, background or banner. In a crawl of the server-rendered pages of 52 sites (L1, measurements/embed-markup), 2 of 4 Vimeo iframes were background loops. proxy.embeds counts pages, rewritten and skipped by reason. docs/security.md covers the rules.

    Dictionary Transport

    A visitor who holds an earlier stylesheet or script of a directory can fetch the next one as the difference from it. dictionary implements this for Chromium 130 and later (RFC 9842). The proxy marks public .css and .js responses with Use-As-Dictionary and answers a request that names one of them with Content-Encoding: dcz. spool has no compression library, so the caller supplies the encoder, and Node's zlib does zstd:

    import { promisify } from 'node:util';
    import { zstdCompress } from 'node:zlib';
    import { spoolProxy } from '@drupflare/spool/proxy';
    import { memoryStore } from '@drupflare/spool/stores';

    const compress = promisify(zstdCompress);

    export const proxy = spoolProxy({
      origin: 'https://origin.example.edu',
      spool: { store: memoryStore() },
      dictionary: {
        encoder: async (dictionary, input) => new Uint8Array(await compress(input, { dictionary }))
      }
    });

    The encoder gets the dictionary, the new file and the coding ('dcz', or 'dcb' when formats lists it) and returns the compressed stream. spool adds the coding's header. An encoder that throws, or whose output is no smaller, leaves the plain file. Only responses the proxy would keep as public ones, with no cookie, ever become dictionaries. proxy.dictionary counts registered, encoded, bytesIn, bytesOut and skipped. docs/security.md covers the exposure.

    base names the files that register as dictionaries, as a function of the pathname, a regular expression or a list of them. Without it the browser holds the latest file of each directory it fetched, and the sizing in docs/impact.md shows that choice recovers little. With it the browser holds only the files you name, one per directory, and every other file of the directory is encoded against the base the request names.

    chooseBases picks the bases from a crawl. It takes the site's stylesheets and scripts with their compressed sizes and a delta function that returns the size of one file compressed against another. For each directory and file kind it returns the file whose deltas against the others, each capped at the other file's plain size, add up smallest. That held policy scores a base for a visitor who already holds it. Pass { policy: 'first-visit' } to add the base's own plain size to the sum, for visitors who load the whole group before they hold anything. Neither policy weighs how often a file is requested or how long browsers keep the base, so neither is a proven minimum of total transfer. A directory with one file has no base, and a tie goes to the URL that sorts first. baseMatcher turns the choices into a base function.

    import { promisify } from 'node:util';
    import { brotliCompressSync, zstdCompress } from 'node:zlib';
    import { baseMatcher, chooseBases, spoolProxy } from '@drupflare/spool/proxy';
    import { memoryStore } from '@drupflare/spool/stores';

    const compress = promisify(zstdCompress);

    const crawl = [
      { url: 'https://origin.example.edu/css/a.css', kind: 'style', text: '.a{color:red}.b{margin:0}' },
      {
        url: 'https://origin.example.edu/css/b.css',
        kind: 'style',
        text: '.a{color:red}.c{margin:1px}'
      },
      {
        url: 'https://origin.example.edu/css/c.css',
        kind: 'style',
        text: '.a{color:red}.d{margin:2px}'
      }
    ] as const;

    const bytes = (index: number) => Buffer.from(crawl[index]?.text ?? '');

    const choices = await chooseBases(
      crawl.map(({ url, kind, text }) => ({ url, kind, plain: brotliCompressSync(text).length })),
      async (file, dictionary) =>
        (await compress(bytes(file), { dictionary: bytes(dictionary) })).length
    );

    export const proxy = spoolProxy({
      origin: 'https://origin.example.edu',
      spool: { store: memoryStore() },
      dictionary: {
        encoder: async (dictionary, input) => new Uint8Array(await compress(input, { dictionary })),
        base: baseMatcher(choices)
      }
    });

    On the 10 Drupal sites of the reading, a base chosen this way and already held by the browser saves 30% of the stylesheet and script bytes at the median site (L1, docs/impact.md). scripts/measure/dictionary-size.ts records the same choice for a site's crawl.

    📈 Capacity Reports

    @drupflare/spool/report turns peak work and an institution's own limits into three separate results: potential, financial and physical. None is added to another, and any can be empty.

    capacityPlan takes intervals of demand per resource with the part spool avoided, and what one node serves per second within the latency target. It returns the nodes needed before and after, as whole numbers, and how many could retire. perNode.busyMs is the milliseconds of handler work a node does per second, such as 1000 times its cores times a target utilisation. spares, floor, regions and minPerRegion raise the answer for redundancy, and a resource with no avoided, such as memory, does not shrink. intervalsFromWork builds the intervals from the WorkSamples the work series records.

    institutionReport adds the plan, an observed before and after of the same workload from production telemetry, an invoice total before and after, and a ledger of retired equipment. The plan says what could change, observed what changed, the invoices what was paid, and the ledger what was removed. The physical result reads only the ledger, and an entry needs the evidence for its removal. With no ledger the statement reads No physical capacity saving demonstrated.

    import { capacityPlan, institutionReport } from '@drupflare/spool/report';

    const plan = capacityPlan(
      [
        {
          start: Date.UTC(2026, 8, 1, 14),
          seconds: 300,
          demand: { busyMs: 9000 },
          avoided: { busyMs: 6300 }
        },
        {
          start: Date.UTC(2026, 8, 1, 14, 5),
          seconds: 300,
          demand: { busyMs: 7000 },
          avoided: { busyMs: 4900 }
        }
      ],
      { perNode: { busyMs: 700 }, spares: 1, floor: 2 }
    );

    export const report = institutionReport({ plan, planLayer: 'L3' });

    The example needs 14 nodes without spool and 5 with it, a potential of 9, at layer L3 because the numbers are made up. channelRows lists the metered, attributional, capacity and avoided-demand channels as separate rows, and nothing in the module sums them. docs/impact.md says what each one counts.

    🚫 Out of Scope

    • spool never authorises on the client. The device holds only what the server already sent that principal.
    • It never shows a hard route past its bound without validating it first.
    • It never writes. Your application owns every write, and invalidate only announces one.
    • It never infers dependencies from opaque HTML. A route names its tags, or the records it reads, and in proxy mode the origin names them in its cache tag headers.
    • It never replaces a published release file on the CDN.
