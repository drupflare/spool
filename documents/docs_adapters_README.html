    Adapters

    Each adapter is one page. The routes, page and spool in every example come from the Quick Start. The compatibility table lists what each framework hands a handler.

    Pick the adapter for your runtime. A runtime that takes a Fetch fetch(request) handler needs no adapter beyond spool.handle. The Node adapter covers any node:http server.

    Adapter Import What it needs File
    Cloudflare Workers @drupflare/spool/stores/durable-object A Durable Object binding for the version vector cloudflare-workers.md
    Cloudflare Pages Functions none (spool.handle) A function that calls next() for the static asset cloudflare-pages-functions.md
    Hono @drupflare/spool/hono app.use('*', spoolHono(spool)) before the routes hono.md
    Elysia none (spool.respond, spool.decorate) An async onRequest hook elysia.md
    itty-router none (spool.respond, spool.decorate) A route that returns undefined for non-spool requests itty-router.md
    Bun none (spool.handle) A default export with fetch bun.md
    Deno none (spool.handle) A default export with fetch, run with deno serve deno.md
    Netlify Functions none (spool.handle) config.path that sends the spool paths and pages netlify-functions.md
    Netlify Edge Functions none (spool.handle) context.next() for the site's response netlify-edge-functions.md
    Vercel Functions none (spool.handle) A vercel.json rewrite and a shared VersionStore vercel-functions.md
    Next.js none (spool.handle, spool.respond) A proxy export and a route handler sharing one store nextjs.md
    Nuxt and Nitro none (spool.handle, spool.respond) h3 toWebRequest in a middleware and a route nuxt-and-nitro.md
